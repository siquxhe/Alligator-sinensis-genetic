## 7. 六个定义的计算式

| 代码 | 分子 | 分母 | 参考空间 | 赋值方式 |
|---|---|---|---|---|
| **C1** strict | structural + replication 类命中 reads | 去宿主 reads（双端计） | PHROG v4 | 类别筛选 |
| **C2** broad | 全部命中 reads | 同上 | PHROG v4 | 无筛选 |
| **C3** 文献值 | Tang et al. 2019 报告的 0.04–4.03% | — | nr + MEGAN4 | LCA |
| **C4** contig | geNomad 判为病毒的 contigs | 全部 contigs | geNomad | contig 计数 |
| **C5** vOTU | 比对到 vOTU95 的 reads | 去宿主 reads | 本研究 9,980 vOTU | read 计数 |
| **C6** 分母对照 | 同 C2 分子 | **去宿主前** reads（`total_reads × 2`） | PHROG v4 | 无筛选 |

**类别归属**（`phrog_annot_v4.tsv` 的 `category` 列）：

- `structural` = head and packaging / tail / connector / virion / neck / baseplate
- `replication` = DNA, RNA and nucleotide metabolism / transcription regulation
- 其余一律归 `other`（含 unknown function 与细菌同源代谢/持家基因）

**分母口径**：`phrog_6samples.tsv` 的 `reads` 列为去宿主后的 reads 数，**双端合并计**；
C6 的分母回到 `host_removal_summary.total_reads × 2`（read pairs × 2）。

## 9. ⚠ 三处必须如实交代的不一致

**9.1 两套流程的 DIAMOND 参数不同（影响「换库」的归因纯度）**

| | 初版（RVDB v32 Unique） | 现用（PHROG v4） |
|---|---|---|
| 库 | 通用病毒蛋白库 | 噬菌体特异库 |
| `--fast` | **用**（灵敏度降低、速度约 10×） | **未用** |
| `--query-cover` | **50%** | **未用** |
| evalue / best-hit | `1e-5` / `-k 1` | `1e-5` / `--max-target-seqs 1` |
| 后处理 | pident ≥ 40%、len ≥ 30 aa | 同 |
| 来源 | `workflow/viral_screen.sh` | `13_calibration/code/phrog6.sh` |

**后果**：C1 从 0.089–0.122%（初版）到 0.589–1.818%（现版），同时变了**库**和**两个灵敏度参数**，两者同向（都使命中变多）。
摘要里「26 倍远小于我们用通用库得到的 171 倍」这句话，严格说把两个因素合在了一个归因里。

**已解决（2026-11-19）**：改为在**同版本 2.0.4、同参数、同一批 2,499,996 条 R1 reads** 下只换库——
RVDB 0.800% vs PHROG 5.511%，**库效应 6.89×**；而 171÷25.9 = 6.60、C1 下限抬升 0.589÷0.089 = 6.62，
三者吻合。**收缩是纯参考空间效应，可以正面写。** 详见 `13_calibration/库效应分离_2026-11-19.md`。

另查明：初版 `--fast` 在 DIAMOND 2.0.4 下报 `Error: Invalid option: fast`，
说明初版用的是本地 **2.2.8**。版本差异也一并记录在该文档 §5。

**9.2 `01_compute_five_denominators.py` 已与 Table 1 脱钩**

该脚本读 `raw_data/` 下 2026-11-12 的 RVDB 中间表，而 Table 1 已于 11-16 换 PHROG。
**已加停用警告**，运行会回退旧数（Fig 2 的 `10 < SPAN < 60` 断言会拦住出图）。
现行 Table 1 由 `make_table1_docx.py` 从 `phrog_6samples.tsv` 生成并校验。

**9.3 C5 的分子允许一 read 多命中**

`run_abundance.sh` 未对多重比对去重（只删 secondary/supplementary）。
若审稿人问「vOTU reads 是否可能重复计数」，需答：**是，这是口径属性而非缺陷**——它衡量的是「比对到 vOTU 集的 reads」，与 C2 的「最佳单一命中」不是同一类计数。此点在 Methods 中应显式写出，否则两轴的比较会被质疑。
