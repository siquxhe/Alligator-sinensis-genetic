# 移动硬盘重组与 Windows 系统镜像：操作清单（最终版）

**日期** 2026-11-10　|　**替代** 此前所有版本

---

## 0. 目标与边界

### 要达成的

1. 移动硬盘重建为 **GPT**，**两个 NTFS 分区**（不留 ext4）
2. 原样保留 sdc 现有 381 G 数据（前主人照片等）
3. 把 sdb 上的 **Windows 系统做成可启动的虚拟机镜像**，存入移动硬盘（不要求物理 USB 启动）
4. sdb 清空并重建为 **ext4 1.8 T 工作盘**
5. iPHoP 库最终落在 sdb（ext4）

### 明确不做的

- 不克隆 sda 的 Debian 系统，移动硬盘不做 Linux 启动盘
- 不要求 Windows 从 USB 物理启动
- 不留 ext4 分区在移动硬盘上
- 不保留 sdb 上的 Windows 实体分区（转为镜像文件）

### 最终格局

| 设备 | 内容 |
|---|---|
| `sda` 240 G SSD | 机内 Debian，原样不动 |
| `sdb` 1.8 T | **ext4**，iPHoP 库 + 分析工作区 |
| `sdc` 2 T 移动盘 | GPT：`sdc1` NTFS 1000 GiB（照片 + 库临时）、`sdc2` NTFS 860 GiB（Windows 镜像） |

---

## 1. 关键前提：为什么镜像不需要改 BCD

Windows 的 BCD 记录的是**分区 GUID**，不是盘符。若在新盘上用 `parted mkpart` 重建分区，GUID 会变，BCD 失效，启动失败。

**解法**：原样复制 sdb 的 GPT 主表与备份表（含全部分区 GUID），再按原分区大小回填内容。这样镜像是 sdb 的"等价克隆"，虚拟机 UEFI 固件能直接按 BCD 找到系统。

---

## 2. 阶段 1｜照片暂存（进行中）

```bash
rsync -rltD --exclude='$RECYCLE.BIN' --exclude='System Volume Information' \
  /mnt/usb2t/ /mnt/disk2t/_usb2t_backup/
```

- 381 G，实测约 90 MB/s，全量约 70 分钟（已有 84 G 可续传）
- 可中断，重跑即续

### 2.1 校验（分区前必做）

```bash
# ① 增量比对：无输出即一致
rsync -rltD --dry-run --itemize-changes \
  --exclude='$RECYCLE.BIN' --exclude='System Volume Information' \
  /mnt/usb2t/ /mnt/disk2t/_usb2t_backup/ | head

# ② 文件数
find /mnt/usb2t -type f | wc -l
find /mnt/disk2t/_usb2t_backup -type f | wc -l

# ③ 体积
du -sh /mnt/usb2t /mnt/disk2t/_usb2t_backup
```

---

## 3. 阶段 2｜sdc 重建 GPT 双 NTFS 分区

```bash
sudo umount /mnt/usb2t

sudo parted /dev/sdc --script mklabel gpt
sudo parted /dev/sdc --script mkpart data   ntfs 1MiB 1000GiB
sudo parted /dev/sdc --script mkpart winimg ntfs 1000GiB 1860GiB
sudo parted /dev/sdc --script set 1 msftdata on
sudo parted /dev/sdc --script set 2 msftdata on

sudo mkntfs -f -L DATA     /dev/sdc1
sudo mkntfs -f -L WINIMAGE /dev/sdc2
```

> 1860 GiB 为边界值：磁盘实际约 1863 GiB，末尾留 3 GiB 给 GPT 备份表。

---

## 4. 阶段 3｜照片回迁

```bash
sudo mkdir -p /mnt/sdc1
sudo mount /dev/sdc1 /mnt/sdc1
sudo rsync -rltD --info=progress2 /mnt/disk2t/_usb2t_backup/ /mnt/sdc1/
```

回迁后按 2.1 三次校验，通过才可删除 sdb 上的暂存。

---

## 5. 阶段 4｜生成 Windows 虚拟机镜像

### 5.1 保存原盘 GPT（含分区 GUID）

```bash
sudo blockdev --getsz /dev/sdb          # 取总扇区数 TOTAL
sudo dd if=/dev/sdb of=/mnt/sdc2/sdb_gpt.img     bs=512 count=34
sudo dd if=/dev/sdb of=/mnt/sdc2/sdb_gpt_bak.img bs=512 skip=$((TOTAL-33)) count=33
```

### 5.2 建与 sdb 等大的 qcow2 并挂载

```bash
sudo qemu-img create -f qcow2 /mnt/sdc2/windows_disk.qcow2 2000G
sudo modprobe nbd max_part=16
sudo qemu-nbd -c /dev/nbd0 /mnt/sdc2/windows_disk.qcow2
```

### 5.3 回写 GPT 与各分区内容

```bash
# ① 恢复 GPT 主表与备份表（含 GUID，顺序不能反）
sudo dd if=/mnt/sdc2/sdb_gpt.img     of=/dev/nbd0 bs=512 count=34
sudo dd if=/mnt/sdc2/sdb_gpt_bak.img of=/dev/nbd0 bs=512 seek=$((TOTAL-33)) count=33
sudo partprobe /dev/nbd0

# ② 确认新盘分区结构应与 sdb 完全一致
sudo parted /dev/nbd0 unit MiB print

# ③ EFI 与 Recovery 原样复制
sudo dd if=/dev/sdb1 of=/dev/nbd0p1 bs=4M status=progress
sudo dd if=/dev/sdb4 of=/dev/nbd0p4 bs=4M status=progress

# ④ Windows 分区：只搬有效簇，不搬未用空间
sudo ntfsclone --overwrite /dev/nbd0p3 /dev/sdb3
```

- `ntfsclone` 只读已用簇（363 G），约 60 分钟；`qemu-img convert` 要顺读 1.8 T，约 5 小时，故不用后者
- MSR（sdb2）为空，无需复制

### 5.4 收尾

```bash
sudo qemu-nbd -d /dev/nbd0
ls -lh /mnt/sdc2/windows_disk.qcow2     # 预期约 400 G
```

### 5.5 虚拟机使用方式

- 新建虚拟机，固件选 **UEFI**，磁盘直接挂载 `windows_disk.qcow2`
- 不需改 BCD、不需修复引导
- 首次启动 Windows 会重新枚举硬件，属正常
- LTSC 2021 的激活可能因硬件变化失效，需重新激活

## 6. 阶段 5｜库临时迁移

```bash
sudo rsync -rltD --info=progress2 /mnt/disk2t/iphop_db/ /mnt/sdc1/_iphop_temp/
```

308 G，约 55 分钟。校验方式同 2.1。

---

## 7. 阶段 6｜sdb 重建为 ext4

**前置**：阶段 3 校验通过、阶段 4 镜像生成完毕、阶段 5 库已到 sdc1。

```bash
sudo umount /mnt/disk2t
sudo parted /dev/sdb --script mklabel gpt
sudo parted /dev/sdb --script mkpart work ext4 1MiB 100%
sudo mkfs.ext4 -L WORK /dev/sdb1
sudo mkdir -p /mnt/work
sudo mount /dev/sdb1 /mnt/work
```

> 会同时清除 sdb1 的 Windows EFI、sdb4 的 Recovery。Linux 用 sda2 的 ESP，不受影响。

---

## 8. 阶段 7｜库回迁

```bash
sudo rsync -rltD --info=progress2 /mnt/sdc1/_iphop_temp/ /mnt/work/iphop_db/
```

校验通过后删除 `/mnt/sdc1/_iphop_temp`。

---

## 9. 回滚

| 时机 | 处理 |
|---|---|
| 阶段 1–3 任一步失败 | 源数据在 sdb 暂存区，sdc 未动或可重来 |
| **阶段 6 之前** | 一切可逆（sdc 已持有照片 + 镜像 + 库） |
| 阶段 6 之后 | sdb 原数据不可恢复，但镜像与库均在 sdc 上有副本 |
| 镜像生成失败 | 直接重做，sdb 未动 |

**唯一不可逆点：阶段 6**。进入前必须确认三件事已完成并校验：照片回迁、镜像生成、库临时迁移。
